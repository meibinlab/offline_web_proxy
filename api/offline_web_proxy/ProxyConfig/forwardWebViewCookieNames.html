forwardWebViewCookieNames

forwardWebViewCookieNames property

Set<String> forwardWebViewCookieNames
final

Names of cookies sent by the WebView that the proxy passes on to the upstream origin.

The proxy keeps the upstream session in its own cookie jar and sends the jar's cookies with every request to origin. Cookies the WebView holds for the proxy origin are a different matter: a script on any page served through the proxy can set them with document.cookie, so passing them on unchecked would let a page plant or shadow cookies the upstream trusts. Only a cookie whose name is listed here is passed on, and only when the jar holds no cookie of the same name for the request URL (the jar's value wins). Every other WebView cookie is dropped.

The same list applies when a request is stored in the offline queue (the stored Cookie header keeps only the listed names, and is left out when none remain) and when a queued request is replayed, including requests queued by 0.25.0 or earlier with every cookie.

  • Each entry must be a cookie name made of RFC 6265 token characters (no spaces, =, ;, ,, quotes and other separators). Names are compared case-sensitively
  • OfflineWebProxy.accessTokenCookieName cannot be listed; the access token is never passed on
  • {'*'} alone passes on every WebView cookie (other than the access token), which is the behaviour of 0.25.0 and earlier. '*' cannot be combined with other entries

start() rejects any other value with a ProxyStartException.

Requests relayed to mirroredOrigins never carry WebView cookies, and their responses never return Set-Cookie to the WebView, regardless of this setting; cookies set by a listed origin are kept in the jar only.

To keep sending a cookie that a page sets in JavaScript, list its name, for example {'locale'}.

Example: {'locale', 'consent'} Default: {} (no WebView cookie is passed on; changed in 0.26.0)
