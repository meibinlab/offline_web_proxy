cacheUserScopedResponses

cacheUserScopedResponses property

bool cacheUserScopedResponses
final

Whether responses that belong to one user are kept in the response cache.

A response always counts as belonging to one user when it carries Set-Cookie or Set-Cookie2, or Cache-Control: private (including private="..."). Otherwise it counts as belonging to one user when either of these holds:

  • the proxy sent Authorization upstream (it is never sent to a mirrored origin)
  • the proxy sent a Cookie header upstream (cookies from the cookie jar and the WebView cookies allowed by forwardWebViewCookieNames; the proxy's own access token cookie is never sent and does not count)

unless its Cache-Control says public, by which the upstream allows sharing it, and its Vary names none of Cookie, Authorization and *. Following RFC 9111 section 3.5, only public counts: s-maxage and must-revalidate allow sharing on the premise of revalidation, which the proxy does not do when it serves from the cache offline.

Note: When the session is a cookie, the cookie jar is sent with almost every request once a cookie exists, so nearly every response, static resources included, counts as belonging to one user unless the upstream marks it public. With false, the cache then stays practically empty after sign-in. With an owner, such static resources are also fetched again after the user changes, before they can be served offline to the new user.

When false, such a response is not stored, and ProxyEventType.cacheSkipped is raised with reason userScoped.

When true and queueOwnerResolver is set, such a response is stored with the current owner (the HMAC the queue uses, never the identifier as given) and is served from the cache only while the same owner is current. Another owner, or a changed owner, gets a miss and ProxyEventType.cacheMiss with reason ownerMismatch. An owner left unresolved (QueuePauseReason.ownerUnresolved) is treated as an owner of its own: what it stored is served only until the owner changes. A response is not stored (cacheSkipped, reason ownerChanged) when a sign-in started or the owner changed while it was being fetched. Before anyone has signed in there is no owner yet: such a response is stored with a mark for "no owner" and served only until an owner is set or the owner becomes unresolved.

Without queueOwnerResolver, such a response is stored and served to whoever asks, as in 0.25.0. Either way, Set-Cookie and Set-Cookie2 are removed from the stored headers; the response returned upstream keeps them. Entries stored by 0.25.0 are not rewritten: their Set-Cookie stays on the device until they expire or clearCache() removes them, but it is never returned from the cache.

Default: true
