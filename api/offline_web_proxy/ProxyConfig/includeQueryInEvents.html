includeQueryInEvents property

bool includeQueryInEvents
final

Whether URLs in ProxyEvents keep their query string and fragment.

Query strings often carry search terms, one-time codes or session identifiers, and events are commonly forwarded to log collectors. While this is false, the proxy removes the query (?…) and fragment (#…) from ProxyEvent.url and from every URL item in the event data (proxyRequestUrl, resolvedUpstreamUrl, resolvedProxyUrl, sourceUpstreamUrl, locationHeader, normalizedTargetUrl and the url of queueResendAttempted).

The externalUrl of redirectHandled is always the full URL, query included, regardless of this setting: for an external launch the proxy answers the WebView with 204 only, so this value is the only way for the app to learn what to launch. Do not write it to logs.

Set to true to receive the full URLs as in 0.25.0 and earlier. The Dart API OfflineWebProxy.recentResendResults always keeps the full URL regardless of this setting, while the status endpoint never includes the query.

Default: false
