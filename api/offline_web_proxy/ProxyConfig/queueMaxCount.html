queueMaxCount

queueMaxCount property

int queueMaxCount
final

Maximum number of requests kept in the offline queue.

When the queue already holds this many requests, a new update request is not stored: the proxy answers 503 with {"queued":false,"error":"queue_full"} and X-Offline-Queued: 0, and emits ProxyEventType.errorOccurred with phase: queueLimit and limit: count. The body tells this apart from a queue that cannot be written, which is answered with {"queued":false}. A request answered with an upstream 5xx keeps that answer, without X-Offline-Queued. Requests already in the queue are never removed by this limit, including when the queue is over it at startup (for example after lowering the value); new requests are refused until enough are sent. Requests moved back from the quarantine store with retryQuarantinedRequest() are not refused by this limit.

Must be between 1 and 100000; start() rejects other values with a ProxyStartException.

Default: 1000
